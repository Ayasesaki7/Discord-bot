# B 站视频解析

`/bv` 和 `!bv` 直接调用 B 站公开的分 P 与播放接口，不再先抓视频网页，
也不依赖经常一起返回 HTTP 412 的视频详情接口。返回的清晰度以 B 站实际
授予的观看权限为准；没有 Cookie 时，公开视频通常会降到 360P。

- 支持 BV 号、完整视频链接、b23 短链，以及链接中的 `?p=2` 等分 P 参数。
- 分段视频会完整合并；分离的音视频需要 ffmpeg。无法合并时不发送半截视频。
- 仅文件太大时尝试较低清晰度；网络、权限、风控错误不重复整套解析。
- HTTP 412/429 或 API 风控后默认冷却 120 秒，可通过
  `BILIBILI_RISK_COOLDOWN_SECONDS` 调整。冷却范围为当前 BOT 的 B 站解析模块。
- B 站 Cookie 只发给 B 站 API，不随媒体下载请求发送到 CDN。
  Netscape 导出文件会按域名、路径和有效期筛选，兼容单行 Cookie 请求头。
- 下载、备用地址、合并及压缩共享处理期限。超时或取消后保留后台线程的
  临时目录与锁，直到线程退出再清理，避免新任务和未结束的下载互相干扰。
  分享文案末尾的中文标点不会再被当成短链或分 P 参数的一部分。
- 视频使用 Discord Components V2 卡片展示：标题、内嵌视频播放器、
  时长/文件大小/BV 号与原视频链接。斜杠和前缀命令使用同一布局。
- 卡片标题从独立的 `/x/web-interface/wbi/view` 读取投稿原题，不再把 pagelist 的
  `part`（经常是上传文件名）当视频标题。多 P 视频另显示分 P 名称和 P 号。
- 标题查询使用 6 秒网络超时，不按清晰度反复请求；成功缓存 1 小时，失败缓存 5 分钟。
  标题接口风控仅冷却标题查询，不阻断可用的分 P/播放接口。取不到标题时显示
  “B 站视频 · BV号”，不拿上传文件名冒充原题。

这不是访问权限绕过方案。视频被删除、地区/账号没有观看权限，或公开 API
也被限制时，仍可能失败。需要登录时，请更新自己的
`config/credentials/bilibili_cookies.txt`，不要把 Cookie 发到公开频道。
