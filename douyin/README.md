# 抖音视频解析

/dy 链接 或 !dy 链接 会发送包含标题、内嵌视频、时长、大小和
「在抖音打开」按钮的 Discord Components V2 卡片（discord.py 2.6+）。
这是实际上传的视频附件，不是把链接伪装成播放器。

## 无水印播放流

分享页可能在 `play_addr` 中返回 `/aweme/v1/playwm/`，它不是无水印流。
现在优先选择页面提供的普通播放流；若只有官方 `aweme.snssdk.com` 的
`playwm` 地址，则使用同一视频 ID 的 `/aweme/v1/play/`，去掉分享水印参数。
不改写其它网站的路径或签名 CDN 地址，不使用 `download_addr` 的水印版。

第三方结果优先 `nwmplay` 等无水印字段，排除 `wmplay` 及其嵌套内容；
yt-dlp 选择器排除标注 `watermarked` 或 URL 带 `playwm` 的格式。
下载跳转若明确退回水印流则失败，不悄悄发送它。这里选择的是原站
无水印版本，不裁剪、模糊或抹除作者已嵌入原视频的文字／LOGO。

## 解析与 token

视频解析不调用大模型，不消耗模型 token。默认先读取官方手机分享页
`https://www.douyin.com/share/video/<作品ID>/`（不再使用经常只返回空壳的
旧 `iesdouyin.com` 入口），
仅使用页面明确返回、且作品 ID 匹配的播放地址；此路径不发送登录
Cookie、不使用第三方 API token，也不生成签名或处理验证码。

公开页如果只返回空壳、验证页、登录限制或作品已不可用，免凭证解析会
失败。HTTP 200 并不代表拿到了视频，不能保证所有公开视频都免 Cookie。
此时若配置了 Cookie，先用现有凭证读取同一官方分享页，再尝试 yt-dlp、
显式启用并配置 Cookie 的 F2，以及用户自行配置的第三方解析接口。
凭证仅发送给域名和路径匹配的抖音 HTTPS 页面，不发送给视频 CDN，不跟随
跳转到其它站点或明文 HTTP。Cookie 只加载到本次任务的内存中，不回写原文件。
没有配置第三方接口时不会自动选用陌生服务。

yt-dlp 在视频详情接口未返回数据时统一提示 fresh cookies，并未真正检测
Cookie 是否过期；不能据此直接归因为凭证失效。服务器可能只在详情 API 上
被拒绝，但官方分享页仍正常提供同一作品的可播放数据。

相关环境变量见 .env.example：

- DOUYIN_PUBLIC_SHARE_ENABLED=true：优先尝试官方分享页（免凭证，再按需带现有 Cookie）。
- DOUYIN_USE_F2=false：F2 改为主动启用的备用方式；已有显式配置仍生效。
- DOUYIN_RISK_COOLDOWN_SECONDS=120：访问被拒绝后的重试冷却。
- DOUYIN_COOKIE_FILE：可选的受保护 Cookie 文件。不会自动扫描个人桌面/
  Downloads；兼容原有项目内 Cookie 路径。
- DOUYIN_PARSE_API_URL[S]：可选备用接口，最多尝试 3 个。接口是否收费或
  要求 token 由该服务决定，与 BOT 的 AI 配置无关。

## 失败与资源管理

解析鉴权失败不再按 1080/720/480/360 重复发送同样的请求；yt-dlp 内部
网络重试关闭，每条解析路径仅尝试一次。视频超过上传限制时优先本地压缩，
第三方视频也会探测时长。文件受总下载大小、Content-Type、完整性检查约束，
下载地址与每次跳转不得指向本机或内网。

达到处理时限后不会删除仍被下载线程使用的目录。后台工作退出、清理完成
前保持下载锁，新的命令会收到“正在处理或清理”的提示，不会不断堆积请求。
日志记录成功的解析路径或经过脱敏的错误，不应输出 Cookie 或带签名直链。

yt-dlp 只读入本次任务的 Cookie 副本（过滤无关域名和过期项），不再覆盖
凭证管理保存的原始文件。F2 的日志和数据库也隔离在本次任务目录；即使
进程退出码为 0，若 HTTP 403/429 且没有视频，仍报告访问失败，不当成成功。
后续备用方式的“没找到文件”不会再掩盖前面的 Cookie/原站拒绝原因。

回归测试：python -m unittest discover -s tests -p "test_douyin*.py" -v
测试不向 Discord 发消息，也不需要真实 Cookie。
