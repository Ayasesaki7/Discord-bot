# 音乐模块

保留现有 QQ 音乐搜索、歌单/专辑导入、直链点歌、顺序/随机播放和 Agent 控制。
音乐面板和 Agent 使用同一份服务器队列；面板操作也要求用户在 BOT 所在语音频道。

## 频道限制

- 点歌、导入、面板和播放控制仅可在自己已加入的语音频道的文字聊天区操作。
  人在语音里但去普通文字频道、帖子或另一个语音频道发指令，也不能控制播放。
- Agent 在普通文字频道仍可查询状态/队列，但 `allowedActions` 不会宣称可以点歌、
  暂停等操作；宿主会在搜索/连接前拒绝不合规请求，不靠模型自觉遵守。
- 搜索/连接结束后重新检查位置，防止提交旧面板或等待期间换频道仍能入队。
- 面板与失败提示绑定真实语音连接，后续点歌不能将它们挪到文字频道。
  更新时若发现跟踪中的旧面板在错误频道，仅撤下这张 BOT 音乐面板并在语音区重建，
  不删除其他聊天消息；重建保留原来的封面、歌词与队列功能。

## QQ 歌曲搜索

- 面板候选、批量点歌和 Agent 共用 QQ 正式歌曲搜索
  `music.search.SearchCgiService / DoSearchForQQMusicDesktop`，不再使用 smartbox 联想接口。
- 原始输入优先；无合适结果时整理全角符号、书名号、歌手/歌名分隔和常见点歌句式。
  保留英文撇号、特殊符号和 Live、Remix 等版本信息，不做聊天关键词触发。
- 按歌名、歌手和完整版本标题匹配排序，同等相关时保持 QQ 顺序；按 MID 去重。
  候选直接使用完整搜索元数据，不再逐首额外请求详情。
- 一次点歌最多尝试 3 个不同关键词，每次网络超时 10 秒；接口错误立即停止扩展，
  不用多个接口反复重试。复杂语义仍建议 Agent 提取“歌名＋歌手＋版本”传入。

## 下载与缓存

- 同一音源使用一个共享下载任务，多个服务器同时点同一首也不会重复下载。
  取消一个等待者不会中断其他等待者；下载结束后才释放任务和清理锁。
- 不同音源最多同时处理 4 个。QQ 音源、直链都分块读取，单文件上限
  200 MiB，HTTP 下载总时限 60 秒；拒绝错误页、不完整文件、本机/内网地址。
- 音频完整解码后统一生成 48 kHz 双声道、128 kbps Opus 缓存，再原子发布。
  Discord 语音本身使用 Opus；这里不是无损下载，而是避免每次播放重复编码。
  播放器使用 Opus 直通，不把 FLAC 文件改名成 MP3。
- 自动音质按 FLAC → MP3 320k → MP3 128k → M4A 逐档尝试；坏文件、下载不完整
  或失效链接只跳过该档，不会因为高码率 MP3 失败而把低码率一起跳过。
  同一坏文件不会因返回了新签名重复下载，全部档位失败后才尝试原有备用源。
- QQ 获取/下载/转换合计最多 180 秒，每档最多下载一次（403 刷新凭证后可重试一次）；
  403 最多触发一次凭证刷新，刷新不占用音质降级机会；仍被拒绝或遇到 429 时
  QQ 音频通道冷却 120 秒。同曲下载失败冷却 60 秒。
  这些措施不能保证恢复平台拒绝的付费、下架、地区或风控受限资源。
- 官方音源不可用时按 `MUSIC_FALLBACK_SOURCES`（默认 `bilibili,youtube`）依次搜索
  备用音源；一个来源被风控、无匹配或文件损坏时继续尝试下一个。已知歌曲时长时
  只接受前 3 个结果中时长相差不超过 10%（至少 15 秒）的一个，避免翻唱、串烧和循环版。
  B 站未登录时搜索经常被风控（412）；配置 Netscape 格式的 `BILIBILI_COOKIE_FILE`
  后会把它的临时副本交给 yt-dlp，不改写原凭证。YouTube 在机房 IP 上通常要求登录。
  每次备用下载使用受控子进程，90 秒超时且不做内部重试；转换 120 秒超时，
  超时/取消会终止处理进程再清理文件。
- 缓存使用 v2_哈希.opus 文件名。正在播放、队列中和正在下载的缓存受保护。
  其余缓存保留 30 天（`MUSIC_CACHE_MAX_AGE_HOURS`），超过 20 GiB 软上限
  （`MUSIC_CACHE_MAX_MB`）时优先淘汰最久没播放的非活动缓存；命中缓存会刷新时间。
  旧 MP3 缓存不会直接复用，会随原有缓存清理规则逐步清理。

## 播放与交互

- 下载完成后重新核对歌曲、播放轮次和语音连接。停止/换歌后旧任务不会重新开播。
- 对重复/过期结束回调去重。连续 3 次失败后停止自动尝试并保留剩余队列。
- 随机播放先确定下一首，预加载与实际播放一致；同一首不会反复预加载。
  顺序播放时额外预取后续曲目，共预加载 `MUSIC_PRELOAD_DEPTH`（默认 3）首；
  后台预取全局最多占 2 个下载名额，QQ 音频冷却期间暂停预取。
- 面板更新串行化，临时编辑失败不会补发重复面板；真正被删除后才重建。
- 停止按钮先确认交互，再等待断开语音，避免超过 Discord 响应时限。
- 队列选择以歌曲对象确认，不按过时的列表下标给另一首歌插队；队列上限 200 首。
- 面板以颜色和文字区分加载、播放、暂停、失败、断线；展示待播时长和真实下一首，
  按当前状态启用按钮，提供刷新。保留自定义播放/进度表情，不重复改写封面链接。
- 队列可移除所选歌曲；清空待播先私密确认，保留当前歌曲以及确认期间新加入的歌曲。
  确认时再次检查操作者是否仍在同一语音频道；过期选择不会删除另一首同名歌曲。
- 加载或失败状态也可跳过；先作废旧播放轮次，再停止音频，避免结束回调额外跳歌。

## 逐句歌词与故障恢复

- QQ CDN 可能把正常 MP3 标为 `application/x-www-form-urlencoded`；下载器会检查
  ID3/FLAC/Ogg 等文件头后隔离下载，仍需完整解码成功才能成为播放缓存，不盲信 MIME。
- 面板和 Agent 共用同一个加歌入口。失败曲目不会一直占住播放器；主动重新点歌后
  会恢复剩余队列，保留待播顺序，且不会打断仍在播放、暂停或正常加载的歌曲。
- 默认启用 QQ 逐句歌词，到 LRC 下一句的时间点更新同一张卡片，暂停时冻结。
  密集时间戳合并到最多每秒一次，长间奏仅每 10 秒刷新进度；受 Discord 网络延迟和
  限速影响，不保证逐字、毫秒级同步。歌词加载完成、暂停恢复时重新安排时间点。
  支持毫秒、多时间戳、offset、Base64；不生成或猜测缺失的歌词，不另发消息刷屏。
- 歌词请求不阻塞音频开播，跨服务器共享同曲请求，最多并发 4 个；成功缓存 24 小时，
  空结果或失败冷却 5 分钟，最多 1024 首。无歌词/直链音频照常播放。
- 紧凑面板提供歌词开关；清空待播、刷新收进“更多”，移除无意义的“未知专辑”文字。
- 默认图片保存在 `music/assets/default-cover.png`，无歌曲或歌曲缺少封面时显示；
  有有效歌曲封面时优先显示封面。默认图作为 Discord 面板附件上传一次并保留，
  歌词/进度刷新复用该附件，不持续上传图片，也不依赖第三方图床。

测试：

    python -B -m unittest discover -s tests -p "test_music*.py" -v

包括模拟并发、停止/断线、坏数据和权限测试，以及 FFmpeg 实际生成 Opus、
读取 Opus 包、拒绝损坏音频的离线测试。不连接 Discord 语音，不发送测试歌曲。
