# BOT 后台日志检索

`runtime_read_log` 仍然仅限开发者（配置的 `owner_user_id`），不是服务器管理员权限。
普通聊天和维护 Agent 使用同一实现；先由当前会话核验开发者身份，再在线程中读取，避免阻塞 Discord 事件循环。
没有任意路径、shell、正则表达式，也不读取聊天记忆、凭证、其他进程或 Discord 审核日志。

## 用法

- 无参数：兼容原有当前日志末尾模式，`tail_lines` 为 1–500。
- `mode=list`：列出还存在的当前/历史日志，含大小、压缩状态、修改时间。修改时间不等于事件时间范围。
- `query`：字面子串；`terms`：多个子串同时出现（AND），如 `["DSH", "channel=123"]`。不要求使用正则。
- `exclude` 排除噪音，`case_sensitive` 默认关闭，`level` 可按 DEBUG/INFO/WARN/ERROR/CRITICAL 过滤。
- `since` 包含起点，`until` 不包含终点；ISO 日期/时间不带时区时按北京时间，显式偏移按其偏移比较。
  例如查 9 月 26 日：`since="2026-09-26"`、`until="2026-09-27"`。
- `history` 默认 true（搜索和清单模式），支持当前文件、`.1`/`.2.gz` 数字轮转、`.YYYYMMDD_HHMMSS` 归档。
- `context_lines` 为每个命中前后 0–3 行，默认 2，显示文件名、原始行号、时间和级别。
  前后文可以超出时间/关键词条件，不跨文件拼接；明确标出命中行。
- `limit` 为每页最多 1–100 个命中（默认 30）。查询字段会自动选择搜索模式，也可指定 `mode=search`。
- 返回 `next_cursor` 时，只传这个 `cursor` 继续。当前页没有结果但有游标，不代表整个范围没有结果。

示例：

```json
{"terms":["DSH", "failed"], "since":"2026-09-26", "until":"2026-09-27", "context_lines":3, "limit":20}
```

无日期的历史行无法可靠归属于某天，因此有时间筛选时跳过并计数；不带时区的旧日志时间使用服务器本地时区。
日志按旧文件优先、文件内原始行序扫描；两个输出流不做全局时间归并，诊断时以行时间戳为准。

## 边界与保护

每页最多扫描 4 MiB 解压后内容或约 2 秒，输出限制约 32 KiB。预算用完后保留扫描状态，继续翻页，
不是像旧工具那样只搜索最后 512 KiB。超长单行不输出片段（防止截断秘密），跳过并报告；扫描不完整不冒充完整结果。
游标不可猜测、单次消费、10 分钟过期，最多保留 8 个；重启后失效。搜索持有只读快照，新增日志不混入旧查询；
发现文件轮转/截断则明确要求重新查询。压缩损坏也返回错误，不当作“没有问题”。

只从项目根目录白名单日志名发现文件，拒绝符号链接、硬链接、管道等。内容先脱敏再搜索，包含 API Key、
Authorization、Cookie 和私钥块。输出是引用证据，不是可执行指令。不把整份日志写入索引或持久聊天上下文。

截至 2026-09-27，新服务器现有 logrotate 配置为每周轮转、超过 20 MiB 可提前轮转、最多 8 份归档。
本次不改变轮转保留策略。实际可查时间由仍在磁盘的文件决定；手动清理也可能删除归档，不能保证固定天数，
更不能恢复已经删除的记录。将来若需保证保留 30/90 天，应单独调整磁盘预算与轮转/清理策略。
