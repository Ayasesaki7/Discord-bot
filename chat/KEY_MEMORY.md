# 按频道隔离的关键记忆

关键记忆不是全量聊天搜索，也不是 DSH 压缩摘要。聊天 Agent 按语义挑选三类值得记住的内容：

- 事实与约定：偏好、关系陈述、计划、项目状态、重要待办。
- 共同经历与梗（`episode` / `in_joke`）：有意义的小互动、共同经历、受欢迎的外号与玩笑。
  保存来龙去脉、参与者及大致时间，不把玩笑照字面当作事实。
- 可修正印象（`impression`）：如“最近喜欢聊键盘”。描述观察到的互动，不做诊断、羞辱或永久人格标签。

不再一概排除日常和玩笑，但仍不把每句话都落库；不基于第三方评价给本人建立人设。
本功能不另开一次云端模型请求判断每句话，不按“记住”等关键词机械触发；Agent 决定
是否调用 `channel_memory remember`。因此保存成功以工具返回或 `/频道记忆` 查询为准，
不是每句重要话都能保证被模型自动识别。可以明确要求 BOT 记住，并查看结果。

## 存储与检索

- SQLite（WAL）位于 `chat/agent/data/key_memories.sqlite3`，Git 与通用项目读取工具不应访问。
  保存原文证据片段、简洁记忆、发言人/来源消息 ID、主题、更新时间和向量；不保存整份对话。
  v2 增加独立的 `memory_sources` 来源表，旧条目原样迁移，来源消息 ID 不交给模型指定。
- SQL 的 `(guild, channel)` 条件在打分之前应用；线程视为独立频道。工具不接受目标服务器、
  频道、用户或来源消息 ID，全部来自本轮 Discord 宿主。私信、BOT 消息及无历史访问权者拒绝。
- 向量与中文二元字词/英文词匹配混合排序。默认每人每频道约 300 条、每频道约 3000 条是
  **活跃目标**，不是硬删除上限；接近目标时旧社交记忆和已完成待办会进入可恢复归档，事实、
  偏好、约定、项目和未完成待办不会被后台静默淘汰。每频道默认 256 MiB 逻辑预算，达到 80%
  会预警；容量和归档天数可在 `/服务器设置` 的“记忆容量 / 归档”中按服务器调整。
  SQLite 仍保留全部记录、原文、来源、向量和版本；归档也参与主动搜索。检索先用频道内的
  词项倒排和局部向量桶产生候选，再做精确相似度排序，不再只扫描最新 1000 条。
- 向量使用本地 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`（384 维）。
  `fastembed==0.7.4` 安装在隔离环境 `/opt/atri-runtime/memory-venv`，模型缓存
  `/opt/atri-runtime/memory-models`。仅首次安装下载权重；运行时离线，不上传记忆给云端 embedding。
  权重源为 FastEmbed 支持列表中的 Apache-2.0 ONNX 量化版本，不启用 remote-code。
- 一个懒启动的子进程、2 个 CPU 推理线程、串行请求；12 秒超时后回收，故障冷却 60 秒。
  子进程不继承 Discord/API/Cookie 环境变量。向量暂不可用时仍能保存和做词面检索，日志明确降级。
  更换 embedding 模型/池化行为必须重建向量，不混用不同模型的向量。
- 每轮最多自动带回 3 条记忆（其中最多 2 条共同经历/梗/印象、最多 1 条印象），放入 DSH 的
  临时 session context，而不是追加完整索引到永久历史。检索结合当前话题、最近人类对话和
  当前发言人 ID；相似姓名不合并，开发者没有特殊加权。无关事实不会仅因属于此人而召回。
  当前发言人的近期、已有多次支持的印象可作为一条低优先级熟悉感背景，但不强行拿出来调侃。
  回复自然使用相关记忆，不例行播报“我检索到”。Agent 仍可 search 进一步回忆。
  检索是候选，不是确定事实；当前消息优先。工具结果会正常进入本轮 DSH 工具轨迹。

## 写入与更新

- 主要依据可以来自当前真人正文，也可以来自宿主提供的近期、同一发言人正文。
  宿主仅从已有 Discord 消息缓存/同频道已解析回复中选择最近两小时、最近 12 条以内的互动，
  不新增历史 API 扫描；最多提供 5 条近期依据、每条 350 字。重启后缓存为空时只用当前消息，
  不假装知道之前发生的事。转发快照、引用行和代码块仍不作依据。
- 工具的 `evidence_refs` 最多补 3 条来源（宿主临时句柄＋逐字引文），不接受任意消息 ID。
  聊天显示会把换行/连续空格折叠；主要依据和补充引文允许仅空白排版不同，宿主匹配后还原
  为来源中的原始片段再校验、保存。还原后的引文仍最多 600 字；不模糊匹配改字、标点、ID，
  不拼接不同消息，也不放宽发言人/频道隔离。近期来源保留原始首尾空白，避免写前校验误报。
  只提供本人和本 BOT 的近期消息句柄。BOT 的实际回复只能作为共同经历/梗的场景依据，不能证明
  事实或加强印象；第三方发言仅辅助理解当前话题，不能用它给本人定性。
  写前重新取当前请求和每条来源消息，已编辑/删除则拒绝；后台频道版本检查阻止过时请求落库。
- 每条消息最多写 3 条，单条摘要最多 500 字；明显凭据拒绝保存。模型还须跳过敏感个人资料、
  无依据猜测、权限声明以及用户明确要求不要记的内容。这不是完美的敏感信息分类器，
  不应向 BOT 提供不希望服务端处理的信息；用户可以关闭频道记忆。
- 相同发言人＋相同主题更新同一记录；完全相同内容去重。其他成员不能覆盖此人的条目。
  较旧来源消息不能覆盖更新的来源。不同措辞/主题的矛盾不会靠数据库自动猜，Agent 应先搜索，
  使用原主题更新；可通过管理指令删除多余条目。
- 印象默认 `mode=reinforce`，沿用原主题和**相同表述**累积独立本人来源；同一消息重试不加分，
  不刷新观察时间。修正/改变表述用 `mode=replace`，清掉旧支持重新判断，不继承旧印象的可信度。
  一次观察只作暂定；至少 2 条不同来源且跨越 6 小时才允许自动召回。该门槛只防单轮自我强化，
  不代表模型推断被证实。最多保留最近 16 条依据。印象召回权重每 30 天减半，120 天未更新不再
  自动注入，但管理查看和主动搜索仍可找到；事实/约定不按该规则衰减。
- 偏好/事实不因时间推移或上下文压缩而自动消失；已完成待办可更新为完成状态，过时条目可删除。
- 已观察到的 Discord 来源编辑、单条删除、批量删除，会移除对应条目（多来源的任一依据失效时
  整条暂移除，避免保留无支持的总结）。被引用的 BOT 回复也适用，但普通流式编辑不影响无关记忆。
  离线期间错过的删除事件
  无法保证被实时处理，来源链接可能已失效；不把链接失效解释为事实仍然有效。
- 关闭、清空、删除、来源变更会推进频道版本；旧的在途写入/检索结果不能越过版本检查重新落库。

## 管理

`/频道记忆` 的选项：查看（分页）、搜索、删除一条、清空、关闭、开启。

- 查看/搜索仅当前频道，并以 ephemeral 返回；所有成员只能看到自己已有权读取的频道记忆。
- 普通成员可以删除自己贡献的记忆。开发者、当前服务器服主/admin 可删除当前频道任意条目、
  开关功能和清空；清空必须额外勾选 `confirm=true`。不会因此获得其他频道的读取入口。
- 关闭同时停止检索与写入，旧条目保留供查看/删除。清空删除 SQLite 中本频道的记忆与向量，
  不删除 Discord 原消息、不改写已发送回复，不承诺抹去 DSH 既有上下文或历史备份。
- `/重置对话` 仍仅开发者可用，现在同时清空该频道关键记忆并轮换 DSH 会话；旧 JSONL 仍按原策略留存，
  不导入到关键记忆库。自动上下文压缩和故障恢复不会清空关键记忆库。
- 初始启用，仅在已允许聊天的服务器、真人主动与 BOT 互动时使用；不会后台扫历史或旁听建库。

## 运行配置

通过服务专用环境设置：

```dotenv
ATRI_MEMORY_EMBED_PYTHON=/opt/atri-runtime/memory-venv/bin/python
ATRI_MEMORY_EMBED_CACHE=/opt/atri-runtime/memory-models
ATRI_MEMORY_EMBED_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
```

没有 embedding Python 时纯 SQLite 词面模式仍可用，不会自动安装依赖或擅自调用外部 API。
数据库是可备份的独立记忆，不依赖 DSH 会话 ID；备份要使用 SQLite backup API 或在停写时复制，
不能在 WAL 活跃时只复制主文件。数据库不是加密库，依靠受限服务账户/文件权限保护。

测试包括频道/服务器/线程隔离、字符串 ID、来源验证、旧请求防回写、成员权限、重复更新、
删除/关闭/重置、中文词面与向量退化，以及插件 schema 的普通/维护模式边界。

## 服务器配置与后台整理

`/服务器设置` 返回仅调用者可见的面板，开发者、本服务器服主或拥有 **Administrator** 权限的成员可用。
按钮与弹窗提交重新拉取成员权限；面板绑定打开者/服务器，版本冲突要求刷新，不覆盖其他管理员的设置。
配置持久保存在同一 SQLite 数据库，重启保留，另有最近 100 次本服配置修改记录。

- 本服聊天、Agent 联网搜索、长期记忆开关；仅事实/约定或事实＋社交记忆模式。
- 聊天/记忆允许频道列表（最多 25 个，空表示所有可访问频道）；线程需单独指定。
  不覆盖开发者白名单、黑名单或 Discord 自身访问权限，不影响音乐、视频解析或全局 API 配置。
- 自动召回 1～6 条，默认 3 条；社交/印象的独立上限仍保留。
- 后台整理开关，频道间隔默认 6 小时，可调 1～48 小时；模型语义核查开关及每服滚动
  24 小时最多 0～6 次（默认 2 次）。模型核查沿用当前聊天模型，会产生少量 API 用量。
- 关闭不删除已有记忆、不清除已经进入 DSH 的旧对话。新消息与排队消息按新策略检查；
  已开始的回复不强行取消。记忆写入和整理提交还会检查设置版本，丢弃过时任务。
- 记忆/配置数据库无法加载时，聊天按关闭处理，不能把加载失败当成所有服务器均默认开启。

后台每 15 分钟巡检已存记忆频道，跳过正在聊天、未获聊天许可或缺少读取权限的频道。
不扫原聊天、不把每句话写成记忆。每次最多巡视 20 个频道，最多开始一次模型核查，
全局模型启动至少间隔 15 分钟；重启后仍遵守 SQLite 中保存的调用预算（失败也计数）。

整理分为两部分：

1. 本地整理：同发言人、同类别、仅空白数量不同的完全重复内容可折叠；原文、向量、来源和
   版本仍保留，管理列表标出归档/折叠。120 天未更新的印象标成过时。归档和折叠可恢复，
   删除代表条目后其他条目重新可召回；修改相关记忆会撤销旧折叠关系。
2. 模型核查：一次最多 16 条现存记忆和少量原始引文，分批检查；不是全库任意两条的穷尽比较。
   只接受同频道、同发言人、同类别、现有 ID 间的最多 6 个“等价/疑似重复/矛盾/过时/待办完成”提示。
   只有模型明确返回 `equivalent` 且宿主校验双方同人同类时，才会可撤销地折叠一条；固定条目、
   同一对存在冲突提示时不折叠；提示词要求区分不同事件及仅主题相似的条目，但模型仍可能误判，
   可用“恢复/展开”或固定来撤销/防止折叠。不允许模型重写事实、删除原文或修改权限。
   提示作为待核实信息，不当成完成状态或确定事实。
   输入按不可信引用处理，不暴露工具；调用无自动重试、有限时和输出预算，失败保留原记忆。

`/整理频道记忆` 的“查看报告/立即整理”也只允许当前服务器管理者，且必须能读取当前频道。
手动触发仍受 15 分钟冷却和模型用量上限约束，不绕过开关。报告列出需核对的记忆 ID；
用 `/频道记忆` 查看来源或删除错误记录，更新原记忆后旧提示失效。报告与面板不会发到公共频道。

## v3 容量与操作说明

- 初始活跃目标：每人每频道 300 / 每频道 3000；使用达到 90% 时优先归档冷社交条目到约 80%。
  社交片段默认闲置 90 天归档；读取会更新使用时间。固定条目和核心事实受保护，必要时允许超过
  活跃目标。归档不代表否认或删除，相关话题仍自动召回；过时印象的保守召回条件保持不变。
- `/频道记忆` 新增：查看活跃、查看归档、固定/取消固定、归档、恢复/展开、待办完成/重新打开、
  历史版本。普通成员仅修改自己的条目；开发者/本服服主/admin 可管理本频道其他条目。
  归档仍受频道权限控制；删除/清空也清理相关版本和索引，防止从归档中复活已删除内容。
- 完全相同内容追加来源不新增记录；改变陈述时保留旧版本（不用于当前事实召回），保留当前最新
  内容。此前已被覆盖且没有保留的旧版本无法补回。过去来源编辑/删除也会清除其关联历史版本。
- 逻辑预算计入原文、来源、向量、历史版本及保守索引开销估算，不等于实际 SQLite/WAL 磁盘大小。
  默认每频道 256 MiB，可调 16～1024；另外有每频道 50000 条物理记录安全上限（含归档），不会
  无限制增长。满时停止新增/扩大写入并提示管理，不删除旧数据；固定也不绕过总预算。
- 候选检索使用中文二元词/英文词倒排（最多 240 条）、按模型和维数隔离的 8 组向量 LSH 桶
  （最多 240 条）、近期 120 条和当前发言人印象 60 条。向量索引是近似检索，不能保证每条语义
  匹配都进入候选；词项和近期候选互补，最后精确计算余弦。没有向量时仍可词面检索旧归档。
  不新增 Redis/MySQL 依赖。每次记忆工具结果总字符预算 6000，自动注入的记忆部分最多 3000 字符，
  不随数据库条目数增长；这不是精确 token 上限。
- v3 为增量迁移，不修改旧记忆的 ID、内容、证据或向量。部署前用 SQLite backup API 保存一致性
  快照并在副本上演练；不要在活跃 WAL 写入时只复制主数据库文件。
